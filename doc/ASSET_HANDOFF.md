## 2. 画面と接続する場所

画像は作品カードのイメージ帯と、節見出し付近の横長の小さな領域に表示します。通常の読書画面の目安は176×110pxです。広い画面では周囲に余裕が生まれ、狭い画面では本文と選択肢を優先して画像を省略できます。したがって、**絵にしか存在しない手掛かりや説明は作りません**。小さくても主題が読める大きな形を使います。

「表紙」は本の題名を焼き込んだ縦長の装丁ではなく、作品カードと読書画面で共有する横長の作品イメージです。全節の既定画像になるため、変化する所持品や人員、現在の残量を断定しない構図にします。場面挿絵は指定の節だけに表示し、その節へ到達するすべての状態で矛盾しないものにします。

音楽は作品ごとに一曲をループさせ、読者が音楽をオンにした後だけ再生します。初期状態はオフです。音楽の有無で分岐や記録は変わりません。まず全節・全結末に使える曲を制作し、場面別の音楽や効果音はこの一覧には追加していません。

## 3. 共通の制作仕様

### 画像

- WebP, sRGB, 8:5前後、不透明背景。標準目安は1600×1000px。生成原本の縦横比と実寸を優先し、寸法合わせの引き伸ばしは行わない。
- PNG生成原本を保存。当初は2560×1600px以上を目安としたが、採用Aと最初の2点は1586×992pxの原本を使用。人工的な拡大はせず、実寸と保存先を採用記録へ残す。
- 配布画像1枚500KB以下を目安。文字と細部を潰す圧縮は避ける。
- Aの少色ドット絵。大きな色面、少ない陰影段階、くっきりした階段状の輪郭を共通基準にする。細かな中間色・材質・滑らかな階調を増やさない。舞台に応じて色相を変え、縦横比を保つ。[採用画像と旧案の記録](ART_DIRECTION.md)を参照する。
- 中央60%×70%に主役を置く。見出し横176×110pxや作品カードの帯で読める大きな形にし、端に人物の顔・重要物を寄せない。
- 題名・UI・読ませる文字を絵に焼き込まない。画像なしでも本文だけで判断できること。

数、文字、機構図、正確な色順が判断に関わるものは、生成画像の偶然に任せません。該当する本文を読んで人が照合し、必要なら正確な図版を別途実装します。表紙で伏線の答え、所有者、救出結果、継承の成否を先に見せないでください。

### 音楽

- Ogg Vorbis, stereo, 44.1kHzまたは48kHz, 128〜160kbpsを目安
- 導入済み21曲は音符・編成のscore.jsonと合成スクリプトを編集原本として保存。24bit WAVを一時生成してOgg化し、WAV自体は常設しない。再生成環境とループ開始・終了位置を記録。
- 約−18 LUFS-I、最大True Peak −1 dBTP以下を制作目安にする。実ファイルで確認。
- 配布音源1曲2MB以下を目安。
- 歌詞・語り・台詞なし。全分岐と全結末で繰り返し聴ける。選択を急がせる大きな山場、正誤の合図、物語内の行動と混同する効果音を避ける。
- 目標の長さは各90秒。音楽として自然なループ境界を優先し、完成時に実際の秒数と小節数を記録します。以下のBPMは制作案であり、実測済みの仕様ではありません。
- 台帳の既定音量は `0.35`。音源自体の音量と合わせ、各作品を移動しても急に大きくならないことを実際に聴いて確かめます。
- 冒頭と末尾をつないで3回以上聴き、クリック音、不要な無音、急な音量の切替えがないか確認します。
- 試聴には [audio-review.html](audio-review.html) を直接開きます。3周再生・末尾5秒からの再生・曲別メモ・JSON保存と読込に対応しています。[手順と確認範囲](AUDIO_REVIEW.md)を参照し、聴いた人が確認欄と判定を記録します。

## 6. 制作からゲームへの導入

1. その回に着手する素材IDを計画から取り出し、作品の本文と作者用根拠を読む。直前の節だけでなく、指定節へ入る条件と本文変種を確認する。
2. 画像または音楽の試作を作り、予定していた寸法・音量・構図・編成で使えるか確認する。試作と採用済みを区別し、この段階で存在しない完成ファイルを台帳へ書かない。
3. 採用する配布用ファイルを一覧の名前で `assets/images/` または `assets/audio/` へ置く。編集原本、使用した指示、作成日、出所、利用条件の記録を残す。
4. 実ファイルが置かれた項目だけ `assets/manifest.json` へ登録する。画像には `src`・`alt`・`position`、音楽には `src`・`title`・`loop`・`volume` を付ける。
5. `node scripts/build-data.cjs` を実行し、`js/assets.js` を再生成する。`node scripts/build-data.cjs --check` で正本と生成物を照合する。指定したファイルの実在も生成器が確認する。
6. `node --test tests/*.test.cjs` を実行する。`index.html` を直接開き、作品カード、本文の挿絵、狭い画面、音楽オン／オフ、ループを確認する。第9回までの全62点について技術検査済み。聴感による3周試聴は技術検査とは別に記録する。
7. 完了した素材だけ `asset-plan.json` の `status` を `installed` にし、採用記録を残す。未着手の作品は `planned` のまま次回へ渡す。素材の導入だけで原稿の状態や結末を変更しない。

ゲームを遊ぶ人は生成コマンドを実行する必要がありません。更新済みの `js/assets.js` と実ファイルを一緒に配布します。

### 登録例

次は、GB01の3ファイルが**実際に完成して配置された後**に使用する登録例です。この登録例は初回計画時の説明を保持したものです。現在は表紙・音楽・場面挿絵とも導入済みで、実際のパス・altはassets/manifest.jsonを正本として参照してください。

```json
{
  "image": {
    "src": "assets/images/gb01-cover.webp",
    "alt": "潮の下の郵便局の作品イメージ",
    "position": "center"
  },
  "music": {
    "src": "assets/audio/gb01-theme.ogg",
    "title": "潮を待つ軒下",
    "loop": true,
    "volume": 0.35
  },
  "scenes": {
    "03": {
      "image": {
        "src": "assets/images/gb01-scene-03.webp",
        "alt": "舟着場の椅子に腰を下ろしたカヨとミヨ",
        "position": "center"
      },
      "music": null
    }
  }
}
```

このオブジェクトを `stories.GB01` へ入れます。場面の `image` または `music` が `null` の場合は、その作品の既定値を引き継ぎます。既定値も `null` なら画像はCSSの表示、音楽は無音です。作品一覧の素材は `library.image` と `library.music` に登録します。

場面の登録は `{ "image": ..., "music": ... }` の形で両方のキーを持ちます。現在の形式は**節IDでの切替えだけ**で、同じ節の状態条件による素材切替えはありません。例えばGB14の炉色、GB15の受入組、GB20の残った錨を一枚の絵で固定してはいけません。状態別の絵を作りたい場合は、先に表示形式と再訪時の選択方法を設計し、その対応を実装します。

### 1点ごとの採用記録

素材を導入するたびに `doc/asset-production-log.md` へ以下を素材IDごとに追記します。第9回までの全62点の記録を作成済みです。

- 素材IDと完成ファイル名。
- 作成日、制作者または生成手段、使用した指示、元にした自作・提供素材。
- 寸法または実際の音源時間、形式、ファイルサイズ、SHA-256。音楽はループの開始・終了位置と実測音量。
- 出所、公開配布の利用条件、必要なクレジット。確認できない事項を取得済みと書かない。
- 配置作品・節、本文と突き合わせた数量・所在・情報開示、画面と音の確認結果。
- 編集原本の保管先、採用状態、残る修正点。
