# 0. 中心命題とv1.2の変更
人物が、知り得たことと大切にしているものから行為を選び、その行為が世界と関係を変え、後から与えられる情報によって意味が読み直される。その過程へプレイヤーが介入できるものとしてシナリオを設計します。
「何をすると何のフラグが立つか」だけでは、人物の判断も物語の意味も説明できません。一方、含蓄や意外性は、位置・数量・情報・因果の矛盾を許す理由にはなりません。
v1.1は、誰が何者で、どこにいて、何ができ、何をすると何が変わるかを契約にしました。v1.2は、それに「なぜこの事態になり、なぜこの人物が動き、その行為でなぜその結果が成立するか」の根拠を必須で結び付けます。
今回の変更は九つです。通常運用と依頼成立、原因と結果の作用機構、目的の発生と変化、制度の効力と例外、証拠の証明範囲、合意と実行の成立、代案と非介入の検査、選択時点の選ぶ理由、補足設定の影響と提示の必要度です。項目の追加だけで終えず、生成前の定義、生成後の照合、違反時の差戻しまでを仕様にします。
「必須」は、そのシナリオの行為・判断・断定を支える範囲に適用します。全人物の人生、全施設の工学計算、全世界の法体系を要求しません。該当しない項目は理由付きで適用外にでき、未定義の必要条件を適用外と呼ぶことはできません。
# 1. 継承する五層と物語の軸
## 1.1 五層
Worldは、固定された過去、現在の実体、場所、資源、法則、制度、出来事を扱います。人物の証言や作者の説明文そのものを世界の正本にはしません。
Agentは、人物ごとの知識、誤認、信念、目的、価値、感情、企み、資源、判断を扱います。本人が知り得ない真相から、その人物の行動を選ばせません。
Narrativeは、何をどの順番・視点・粒度・呼称で提示するかを扱います。見せ方を変えるために、確定した過去を後から変えません。
Audienceは、読者に生じ得る疑問、期待、仮説、誤読、早期理解を扱う作者用の層です。現実のプレイヤーの内心を正確に取得できるとは仮定しません。
Transformation / Revealは、世界、人物、関係、提示、受け手の前提、開示の仕方を変える操作を扱います。誰が何をしたかの再構成と、その行為を何として読むかの再解釈を区別します。
## 1.2 抽象度・粒度・Arc
StoryWorld → Plot → Scenario → Narrative → Textは具体化の系列です。実行JSONは、その全体の代わりにはなりません。
Beat → Scene → Sequence → Episode → Workは構造の粒度です。表示ノードやゲームブックの節は、Sceneと一対一である必要はありません。
Arcは、人物、関係、謎、政治、主題などにまたがる変化です。分岐図の階層とは分けて追跡します。全作品へ同じ謎解きやどんでん返しを課しません。
## 1.3 ドラマの核
Dramatic Kernelには、表面課題、誰の何が懸かっているか、認識の差、両立しない要求、プレイヤーが動かせる部分、結末へ持ち越す問いを記します。
Conflictは敵の存在ではなく、複数の要求がそのままでは両立しない関係です。事情を説明しただけで利害が消えるなら、その説明がなぜ従来の判断を変えるかを示します。第三の解決も、協力・技術・資源・制度上の手段などの成立根拠を必要とします。
教訓や悲哀は、必ず誰かを死なせることや、成功に罰を付けることではありません。守ったもの、引き受けたもの、分からないまま残ったものが、人物の振る舞いへ現れることを重視します。
# 2. 設定・命題・根拠の正本
## 2.1 過去、現在、未来を分ける
開始以前の履歴と、開始時点の状態を分けます。固定過去の最終結果と初期状態が一致し、過去の出来事がプレイ開始時に二重実行されないことを検査します。
開始後の履歴は、実際の行為、人物の判断、法則、保存可能な判定結果から生じます。開始時に真相候補を抽選する作品では、抽選時点と以後固定する事実を宣言します。推理が当たったから真相を変更することは認めません。
「あの時は支道にいた」は、救出後も真であり得ます。「いま支道にいる」は現在地を参照します。未実行の救助は予定であり、帰還済みの事実ではありません。
## 2.2 設定の出典・採用・時間範囲
重要な設定はFact Recordとして、ID、命題、出典、採用状態、適用する作品・地域・人物・時期、固定過去か現在値か法則か、依存する設定、影響する行動・提示・結末を持ちます。
出典の種類は、既存の採用済み設定、観測記録、人物の証言、推論、今回の創作上の補足を区別します。作者が採用した世界の真実と、人物が真実だと主張しているだけの内容も区別します。
採用状態は採用済み、提案中、未解決、廃止です。今回新しく決めた前提は創作上の補足として出典を残します。ユーザーから認められた制作範囲内の通常の補足は作者が決められますが、既存の固定条件に反する改変を補足と呼んではいけません。
q001の新しい二瓶規則は、該当結末で成立する制度変更です。全経路の開始時から存在する規則へ昇格させません。地域限定の慣習を、他地域にも自動適用しません。
## 2.3 根拠を結ぶ関係
重要な行為・推論・合意・結果・描写は、根拠となるIDを参照します。関係の種類として、原因、必要条件、人物にとっての動機、制度上の許可、証拠による支持、結果の確認、提示による再解釈を分けます。
「許されている」は実行した証拠ではありません。「実行したい」は実行できる条件ではありません。「そう信じた」は世界で真である証拠ではありません。これらを一種類の因果の矢印へ潰しません。
各重要断定には、根拠の集合、そこから断定へ進める理由、適用条件、残る反証・別解、確認状態を持たせます。必要条件と十分条件、ANDとORを明示します。「結果が起こると設定したから、その結果が起こる」は作用機構の説明になりません。
根拠の連鎖は、出典付きの採用設定、適用範囲を定めた創作法則、該当する観測・試験などで止められます。世界の全法則を無限に証明する必要はありません。ただし、根拠を止めた前提と、そこから推論した結論を混ぜません。
相互依存する運用や循環は、時間と維持条件を持つ仕組みとして許容します。結論Aを結論Bで、BをAだけで証明する循環は根拠不足です。
# 3. 通常運用と依頼成立：Situation Contract
## 3.1 必須項目
Situation Contractには、通常の目的、担当者と役割、人数・交代・連絡の運用、使う資源、正常に終わったと判断する条件、今回崩れた箇所、崩れたきっかけ、発見時点、依頼時点まで放置された理由を記します。
続けて、依頼人が知っていること、表向きに頼むこと、私的に望むこと、自力・通常の担当者・上位組織で処理できない理由、プレイヤーへ依頼できる立場、依頼の終了条件を結び付けます。
役職名には、実際にする仕事を一文で添えます。正式な担当、見習い、同行者、所有者、管理者、代理人を区別します。名称が魅力的でも、その人物の権限や業務内容を名称だけから推測させません。
## 3.2 検査と適用例
通常なら何が起きるかを再生し、そのどの条件が今回は成立しなかったかを確認します。「いつもこうしている」だけでは、事故が今回起きた理由になりません。蓄積、規模の変化、偶発的な故障、誤判断など、該当する差を置きます。
q001では、一経路を一人で巡灯する通常業務と、新人教育のための同行を区別します。リネが同行を知ることと、正式な当直人数に新人を数えることは別です。新人を帰還確認の対象から消す根拠にはなりません。
q020では、王という通称の説明に加えて、本来の交代運用、途絶えた理由、その後も持ち場を離れない理由が必要です。強い責任感は説明になり得ますが、その偏りが行動や過去から読み取れるようにします。
# 4. 原因と結果の作用機構：Mechanism Contract
## 4.1 必須項目
Mechanism Contractには、対象と範囲、入力・出力、作用の順序または接続、成立条件、処理能力・閾値、所要時間、増減する資源、止まる条件、介入によって変わる箇所、変わらず残る箇所を記します。
物理現象、魔法、生態、経済的な連鎖など、その作品で結末の根拠になる仕組みに適用します。普通の扉を開けるたびに詳細計算は不要です。逆流、増殖、呪いの移動など、常識だけでは結果を一意に補えない仕組みを優先します。
創作法則には適用対象、発動条件、費用、限界、例外を定めます。魔法だから成立する、当地の慣習だから従う、とだけ書いて任意の結果を許しません。現実の法則に依存し、その正しさが結末を左右する場合は、必要な範囲を資料で確認するか、創作法則としての変更を明示します。
## 4.2 数量・時間・介入の検査
保存量は、開始量に発生・流入を加え、消費・破壊・流出を引いた量として説明します。移動しただけで増えないこと、時間を要する変化が瞬時に完成しないこと、試験と本運用の条件が対応することを確認します。
q003では、宿屋の排水がどの経路へ流れ、どの処理能力を超え、どこへ逆流し、浮子が何を検知するかを分けます。鐘を止める介入は警報へ作用し、逆流そのものを除去しません。
放水の時間分散は、放水総量や購入水量の削減を必ずしも意味しません。水売りの減収を結末に含めるなら、実際の使用量・購入量を減らす運用まで根拠に含めます。ここで示すのは因果検査の要求であり、本書への記入で個別クエストを変更したことにはなりません。
一度の試験で確認できる範囲と、長期運用で確認すべき範囲を区別します。「一晩は危険線を越えなかった」から、あらゆる豪雨でも安全と断定しません。
# 5. 人物の判断と目的の変化
## 5.1 Agent CardとPlan Card
Agent Cardには、社会的な立場、表向きと私的な目的、価値、恐れ、守りたい自己像、知識・信念と情報源、使える資源、越えない一線、判断の偏り、代案を持たせます。本人の資源欄は現在の所持・能力の正本を参照します。
主要な振る舞いには、観察される行為、本人にとっての理由、他者からの見え方、後に読み直される意味を記します。すべての仕草を伏線にせず、生活感や余白も残します。
Plan Cardには、所有者、望む状態、信じている前提、他者やプレイヤーへの予測、表向きの提案、隠した利害、資源、見える兆候、妨害されたときの反応、代案、失敗の代価を置きます。企みを見抜かれた人物にも撤回・拒否・逆提案・責任転嫁などの次の判断を与えます。
## 5.2 Goal Transition Contract
目的が新しく生じる、優先順位が変わる、放棄される場面には、人物、変更前の目的と優先順、きっかけとなる出来事、本人が取得した情報、本人の解釈、変化を支える価値や感情、変更後の目的、維持する条件、対応する行動を定義します。
目的を変えるのは新情報だけではありません。疲労、喪失、関係の変化、約束、羞恥、時間切れも理由になり得ます。ただし、どの出来事で何が変わったかを示します。作者が結末に必要だと気付いたことは、人物が目的を変える理由になりません。
当初の主目的、副目的、条件付きの希望、他人から課された目的を分けます。目的が競合したときの優先順や越えない条件を保持します。人物が合理的な最適化をしない場合も、その人物にとっての理由を置きます。
## 5.3 q005への適用
トトの当初の主目的は、排水の詰まりを除いて工房を再開することです。冷水で菌床の増殖を抑えられると知り、保存の可能性を見いだした後に、「食用にできるなら残したい」という副目的が生じます。
保存できる可能性を知ったことは、食用として安全だと知ったことではありません。排水の回復、菌床の保存、糖液の食用確認は別の達成です。
副目的を聞いていない経路でも、焼却で詰まりを解消する選択は成立し得ます。その経路の主人公が、聞いていない保存希望を裏切ったと断定してはいけません。人物の希望がプレイ中に成立した時点と、作者が用意した潜在的な可能性を分けます。
# 6. 制度の効力と例外：Institution Contract
## 6.1 必須項目
Institution Contractには、地域と適用時期、制度の目的、権利・義務・資格の対象、通常の手続、効力を発生させる行為、判断権者、必要な証明、記録と原本の役割、執行者、異議申立て、欠席・紛失・代理・不正の場合の扱いを記します。物語で使わない例外を網羅する必要はありません。
正式な制度、地域の慣習、当事者間の契約、事実上の力関係、本人がそう思い込んでいる規則を区別します。慣習違反が、直ちに法的な無効や処罰になるとは限りません。
制度が公正である必要はありません。不公正な制度も設計できます。その場合は、何を根拠に誰が不利益を課せるのか、対抗する手段があるのか、それを利用できない事情は何かを一貫させます。
## 6.2 行為・証明・効力・執行を分ける
q004では、通行証の紙、資格、登録名義、留置、仮証発行を別の対象として扱います。紙を二枚に複製しても資格は二つになりません。留置を解く権限と、正式資格を認める権限が同じとは限りません。
q018では、金を用意する、支払う、役人が確認する、原本を失効させる、債務が終了する、終了が争われる、という違いを扱います。債権者の欠席で何が妨げられ、何は有効なままかを決めずに、都合に応じて効力を切り替えません。
不正者が再請求を主張できることと、その請求が有効と裁定され、実際に取り立てられることは別です。虚偽の主張だけで赤札や差押えまで描くなら、それを実行する者が何を信じ、どの権限で動いたかをつなぎます。
新しい役所や例外規則を足す場合は、その手段が以前から使えなかった理由と、他の経路へ与える影響を確認します。必須欄を埋めるためだけに行政機構を増やしません。
# 7. 証拠と結論：Inference Contract
## 7.1 必須項目
Inference Contractには、判断する人物、観測または取得した証拠、その出所と取得時点、証拠の信頼性と保管経緯、結論、証拠から結論へ進む論拠、補助前提、競合する説明、反証条件、断定の範囲、未解決事項を記します。
結論の扱いは、可能性、仮説、裏付けあり、当該制度の判断基準を充足、宣言した前提内で確定、といった区別を持ちます。これらは常に一列の強弱になるとは限りません。公的な裁定が出ても、世界の真実と一致する保証はありません。
情報源に接触したという記録は、その情報源が正しく、十分であることの保証ではありません。複数の証拠が同じ伝聞に由来するなら、独立した裏付けとして重複計上しません。
## 7.2 不在と否定の区別
記録にないことから出来事がなかったと断定するには、その記録が対象期間・対象行為を漏れなく含む理由と、欠落・改竄の扱いが必要です。
q006の石入りの箱と入金記録の欠落は、未払いの偽装を疑う材料になります。しかし、それだけで投棄者や全履歴まで一意に確定するとは限りません。断定を保つなら、記録の完全性、証言、本人の説明、金銭の履歴など、残る別解を区別する根拠を整えます。整わなければ結論の表現を狭めます。
q019で重量差を観測したことは、契約上の給金不足を計算したことではありません。当時の単価、計量・換算条件、記録が残る期間を照合し、確認できた範囲だけを不足額とします。
## 7.3 推理の自由と検証
証拠が足りなくても疑いを述べたり、仮説を試したりできます。その入力を、公的に立証した状態と同一視しません。
必要な証拠の代替経路をOR、その経路内で同時に必要な証拠をANDとして定義します。別々のプレイでしか取得できない証拠を合算しません。
検査では、同じ証拠と両立する別の説明を少なくとも関連範囲で探します。残る別解が結末の断定を覆すなら、追加調査、制度上の限定した裁定、断定の弱化のいずれかへ改稿します。証拠名に「決定的」と付けるだけでは合格しません。
# 8. 合意から実行まで：Resolution Contract
## 8.1 必須項目
Resolution Contractには、解決したい問題、変更する仕組み、提案者、影響を受ける当事者、判断権者、同意が必要な人物、その受諾・拒否条件、交渉で変わる条件、費用、資材、人手、技術、所要時間、実行者、確認方法、維持担当、残余の問題を記します。
解決段階は、提案、実現可能性の確認、必要な同意または適法な決定、資源の確保、実行、結果確認、必要なら維持運用を区別します。段階の順は行為に応じた依存関係で決め、一律の儀式にしません。
物理的に強行する行為は、相手の同意なしでも実行可能な場合があります。その場合は強行として権限・抵抗・危険・後の解釈を扱います。「必要な同意が成立した」と偽って記録しません。
## 8.2 なぜ相手が応じたか
不正を指摘された人物が応じる理由は、事実の理解だけとは限りません。証拠を公表される不利益、執行力、代替案による損失軽減、守りたい関係、以前の約束などを具体化します。相手が応じない経路や、提案条件が満たされない場合の扱いも置きます。
承諾を得る選択肢は、必要条件がそろえば承諾される行為として圧縮できます。ただし、プレイヤーの希望とNPCの判断を無条件に同一化しません。相手の判断根拠が不足するなら、承諾を試みる段階として扱います。
q020で費用と補修担当の争いが交代停止の原因なら、補修図の完成だけで工事完了へ進めません。誰が費用と作業を引き受けたかを示すか、その争いを解く交渉を入れるか、結末を計画・一時交代の段階に限定します。採用する方法は個別原稿で決めます。
## 8.3 圧縮と完了の条件
短いシナリオでは、成立条件のそろった一連の作業を一場面・一段落へ圧縮して構いません。画面外の行為にも実行者、資源、時間、出来事と結果が必要です。必須条件が不明なまま「その後すべて解決した」とは書きません。
試験完了、制度の承認、実際の救助、名簿への記載は別の出来事です。名簿が誤っている物語も作れますが、記載だけで世界内の帰還を成立させません。
継続的な清掃や当番で維持する解決には、担当者の承諾、必要資源、頻度、途絶えた場合の影響を定めます。「再発しなかった」と将来を断定する場合は、その期間の運用と結果を後日談として確定します。
# 9. 代案と非介入：Counterfactual Review
## 9.1 比較する基準
事件発生前に通常の手続が働いた場合、依頼時点でプレイヤーが介入しない場合、重要な情報を早く知らせた場合、目につく簡単な代案を試した場合を比較します。
代案ごとに、誰がいつ思い付けるか、何を知っていれば考えられるか、物理的・制度的な可否、資源・時間・危険、本人が選ぶまたは選ばない理由、予想される帰結を記します。
想像できる全行動を実装する必要はありません。作品がプレイヤーへ約束した介入範囲に照らし、明白な代案を採用する、選べない理由を示す、物語の範囲外として明示する、いずれかを選びます。単に作者の用意したボタンがないことを、世界内で不可能な理由にしません。
## 9.2 修正を要する場合
「上司へ連絡する」「別の出口へ回る」「依頼人本人が回収する」「何もしない」が低負担で問題を解くなら、その代案を採用するか、人物や状況に根差す制約を補います。元の筋を守るために、代案の数だけ場当たり的な禁止規則を追加しません。
出口の一つが閉じたことだけでは、別の有効な出口も失われたとはいえません。例えばq010を点検するなら、閉門後の通常経路と縦坑の状態を別に確認します。未帰還と、以後の救助が不可能であることも分けます。
時間制限を代案の不採用理由に使うなら、その時計と時間消費を定義します。実行上は待ち続けられる設計で、選択を正当化するときだけ迫る死を持ち出しません。演出上の緊迫感と、判定に使う期限を区別します。
人物の誤認や恐怖によって合理的な代案が選ばれないことは許容します。偏りに先行する根拠があり、別の情報や介入で判断が変わり得るかを確認します。
# 10. 選択時点の理由：Choice Contractの拡張
## 10.1 読者への約束と世界への行為
Choice Contractには、行為としての選択ラベル、主人公が発想できる根拠、プレイヤーへ提示済みの情報、見えている目的、期待できる利益、時間・費用・危険、不可逆な負担、不確実性、実際の作用、他者の解釈、後へ残る差を記します。
表示してよい条件、主人公の知識条件、実行可能性、結果の成立条件を分けます。同じ意味の条件は共通の述語を参照します。「慰める」と選んだのに重大な告発を実行するなど、入力に含まれない行為を追加しません。
プレイヤーだけが幕間で秘密を見た場合、主人公がその秘密を事実として引用できるとは限りません。疑いを試す、別の根拠から質問する、証拠を求める、といった介入を区別します。
## 10.2 選びうる理由の検査
各選択肢について、その時点でそれを選びうる理由を記します。速さ、費用、危険回避、依頼への忠実さ、特定人物への義理、確実性、関係を壊さないことなどが候補です。すべてを倫理的な苦悩にする必要はありません。
誤った選択、無謀な選択、悪意ある選択も扱えます。ただし、その意図や当時の見通しを、作者だけが知る結末から逆算して責めません。必ず全選択肢を同じ期待値や有利さに調整する必要もありません。
q019で原因を調べず秤を交換する選択を残すなら、故障だと考える理由や、その行為を選ぶ実際の利点を点検します。既に正常と確認した後なら、それでも交換する別の理由が必要です。同じ選択でも取得済み情報によって意味が変わります。
## 10.3 分岐の意味と作品群の多様性
世界、知識、関係、責任、解釈のどこが変わり、以後どこへ残るかを定めます。態度を表す小さな選択も残せますが、実質のない差を重大な結末分岐とは呼びません。
informed、contract、compromiseは特定作品の結末IDであり、本モデルの必須三分類ではありません。「調査するほど善い」「依頼どおりなら愚か」「妥協は必ず先送り」という対応を固定しません。契約の履行が妥当な解決になる作品、真相を知っても解決できない作品、関係の変化で終わる作品も扱います。
複数作品を生成するときは、事件の仕組み、人物の要求、介入方法、情報の配置、分岐と合流、結末に残る差を比較します。名詞や舞台を変えただけで同じ構造が反復していないかを検査します。
# 11. 作者向け制約と、読者へ伝える情報
## 11.1 AI向け注釈
個別の事実項には、次の注釈を付けられます。
「以下の事実は世界設定上の整合性を保つための制約です。これらを台詞、説明、選択肢としてシナリオへ直接反映する必要はありません。ただし、生成・改稿時に矛盾させてはいけません。」
この注釈は、制約を実行上も無視してよいという意味ではありません。また、事実項を機械的に台詞へ挿入する指示でもありません。
## 11.2 Presentation Necessity Contract
重要な設定には、作者だけが保持する背景、選択を理解するための前提、推理に用いる手掛かり、後で意味を変える情報という提示上の用途を付けます。複数の用途を持たせても構いません。
選択の理解に必要な情報には、誰へ、どの判断までに、どの意味が伝わればよいか、説明・物・行為・会話など何で伝えるか、未提示の経路でどう扱うかを定義します。事実を全文説明することを要求せず、必要な意味が伝わることを求めます。
例えば当直の人数規則を説明しなくても、新人が教育のために同行したと分かれば人物関係を理解できる場合があります。作者向け注釈を読まないと何を頼まれているか分からない状態は、本文の提示不足です。
## 11.3 追加設定の影響
設定の追加・変更時には、依存する行動、推論、制度、結末、他クエストをたどって再検査します。廃止した設定を前提とする本文や、改稿前の検査結果を残しません。
「矛盾しない」と「原因や判断の説明として十分である」は別です。両方を検査します。追加設定で元の問題を説明できても、より簡単な別解が生じた場合は再評価します。
条件と関係の把握に使わず、世界の雰囲気を作る背景も保持できます。すべてをフラグ化したり、使わない設定を一律に削ったりしません。一方、未採用の補足案を世界観wikiの確定事項へ自動登録しません。
# 12. 実体・所在・身体・物品・状態
## 12.1 実体の同一性
会話、移動、救助、受け渡し、判断、証言に関わる対象へ固定IDを与えます。Entityには、種別、呼称、役割、関係、出典、確定度を持たせます。本名がなくてもIDを定義できます。
同じ老人への「灯番」「あの人」という呼称は同じ実体を参照します。偽名・変装では世界の実体と観測者の同定を分けます。故人、回想中の人物、現在生存している人物を混ぜません。
集団は一つの実体にまとめられますが、一部だけ別行動するなら、個体または分遣隊と構成員数を定義します。背景人物が行為や証拠の担い手になった時点で、検査できる対象として登録します。
## 12.2 所在・接続・身体能力
場所はID、包含関係、接続、移動手段、通行条件、必要な時間を持ちます。同じ入口という呼称でも、地下入口と地上の詰所は必要に応じて分けます。広い同一空間では、接触や会話の範囲も必要な粒度で定義します。
実体の直接の所在は、場所・容器・保持者などの一つを正本として参照します。包含の循環を禁止し、保持関係をたどって実効位置を求めます。物品の運搬中は保持者に従い、降ろすと所在を更新します。
身体は、生存、意識、歩行、介助があれば移動可能か、発話可能かなど、行為で使う軸を定義します。既存のHPや状態異常が正本ならそれを参照します。会話場面へ入っただけで回復したことにしません。
遠隔会話、瞬間移動、分身、夢を扱う場合も、参加形態と法則を定義します。整合検査を一括無効にする例外を設けません。
## 12.3 所持・所有・数量
物理的な保持と所有権、容器と内容物、複製できる情報と固有の原本を分けます。貸与で保持者だけが変わる場合と、贈与で所有も変わる場合を区別します。
数量には単位、値域、容量、分割可能性を定めます。分配は出し手の減少と受け手の増加を対応させ、消費・生成・破壊には出来事を持たせます。破壊された物の履歴を、最初から存在しなかったことへ書き換えません。
## 12.4 状態台帳
State Recordには、IDまたはpath、意味、型、定義域、単位、初期値、正本か派生値か、許可された更新者、参照する行動と提示、寿命、可視範囲、不変条件を定義します。初期値は実際の初期化処理まで対応させます。
型はboolean、有限enum、範囲付き数値、実体参照、集合などから選びます。参照先の存在と種別も検査します。正本は宣言した行動、初期化、明示した移行からだけ更新し、派生値は読み取り専用にします。
世界の事実、人物の認識、提示履歴、関係・約束、客観的な戦績、進行位置は別の意味です。既存の所持品や能力から計算できる現在値を別フラグへ重複保存しません。現在の同行と、以前に同行へ同意した履歴も区別します。
不明は、作者未決定、世界では確定しているが人物には未知、旧セーブ等から復元不能、の三種類を分けます。行為の成否に必要な作者未決定値を、都合のよい値で埋めて完成扱いにしません。候補を許す場合は、許した候補ごとの条件を検査します。
# 13. 行動・遷移・失敗・確定
## 13.1 Action Contract
行動には、ID、主体、対象、行為種別、動機または目的遷移への参照、物理・資源・知識・制度上の前提、所要時間、成功効果、失敗の種類ごとの効果、観測者、出来事、再試行方針、作用機構または制度への参照を与えます。
意思決定の理由と物理的な成功条件は別に検査します。閉じた扉を開いていると信じて進もうとすることはあり得ますが、信念だけで閉じた扉を通過させません。
移動は対象と通る接続を持ち、待機している無関係な人物を動かしません。手渡しは現在の保持者、接触可能性、受け手の能力と必要な同意を検査します。観測は情報源との接触と、観測から得られる命題の範囲を確認します。
## 13.2 原子性と中断
不可分な行為は、前提検査、変更案、変更後の不変条件、状態と出来事の一括確定、結果提示の順に処理します。表示時だけでなく選択確定時にも前提を再検査します。
戦闘や移動の途中で失敗・中断・介入があるなら、保存可能な中間段階を定義します。実際に消費した薬や戦闘結果を、救助が未完了だからと一律に巻き戻しません。救助の成功効果は成立後にだけ確定します。
行動定義IDと行動インスタンスIDを分けます。再送・再読・セーブ再開で同じ取引や報酬を二重確定せず、繰り返し可能な取引まで一生に一回へ制限しません。
原子的な処理をアダプターが保証できない場合は、明示した処理段階と再開・補償を実装するか、未対応とします。成功文を表示することを状態更新の代わりにしません。
## 13.3 Transition Contract
遷移には、出発ノード、到着ノード、発火主体、条件、参照行動、成功先と失敗先、反復方針を持たせます。状態効果を行動と遷移の双方へ手で重複記述しません。
意図した失敗終端は、その帰結と再開方針を定義します。実行可能な選択が意図せずなくなる状態を、物語上の悲劇とは呼びません。
# 14. Scene・Beat・情報開示・描写
## 14.1 Sceneと合流
Sceneには、ドラマ上の問い、参加者それぞれの要求、言われないこと、プレイヤーが動かせる部分、失われ得るもの、時間、場所、視点、参加形態、入口条件、行動、本文変種、出口条件、後へ残る差を持たせます。
現地同席、遠隔通信、回想、引用、話題としての言及を区別します。入口条件は検査であり、それに合わせて人物を自動移動・回復させる命令ではありません。
Beatでは、世界、認識、目的、関係、選択可能性、読者の期待の何が変わるかを捉えます。すべての文へ複数の役割を強制しません。
合流では、到達する各状態で本文と選択が成立するかを確認します。排他的な本文条件の重複と欠落を検査し、既に救出した人物、消費した物、交わした約束を初期状態へ戻しません。再読、再訪、時間経過を伴う再訪を区別します。
## 14.2 四つの情報所在とReveal Contract
作者の真実、人物が取得した内容、プレイヤーに提示済みの内容、プレイヤーが実際に理解した内容は別です。取得した証言の内容と、それを真実だと信じることも分けます。
Revealには、明かす事実、前後で変わる解釈、伏線、競合する説明、必要な証拠、開示条件、効果的な局面、遅くとも必要な局面、早期発見時の応答、取り逃した経路での扱い、読み直される行為、開示後にも残る対立を持たせます。
手掛かりと断定の間はInference Contractで支えます。開示のために固定過去を変更せず、早期正解者へ理由なく指定の手掛かり巡回を強制しません。真相が分かってから交渉や決断が始まる構造も、最後の一文で意味が変わる構造も許容します。
## 14.3 演出とPresentation Assertion
何を見せるか、順序、視点、細かさ、呼称、信頼性を作者が設計します。仕草、触れない品物、台詞と行動のずれ、沈黙、反復、対照、場面の切れ目を、フラグとは別に保持します。
重要な提示単位には、本文、参照実体、命題、時点、話者または視点、断定の種類、成立条件、根拠ID、提示による情報更新を記します。
現在の客観描写は現在状態、過去の説明は該当履歴、証言は発話と伝達、信念は本人の認識、予測は主体と根拠、確定した後日談はそこまで進めた出来事を参照します。嘘の証言を世界の真実との不一致だけでエラーにせず、嘘をつく知識と理由を検査します。
地図に書いた位置は、観測時刻付きの情報です。音の方向しか知らない経路では捜索範囲として記します。人物が後で動いても、地図の記載を自動的な現在位置へ読み替えません。
本文に契約未登録の行為や断定が混入していないかを逆方向にも読み直します。登録した命題だけを検査して本文全体の整合を保証したことにはしません。
# 15. 戦績・NPCの自律・時計・保存
## 15.1 戦績から人物の判断へ
戦績は実際の戦闘の正本です。その記録を人物が取得した経路、人物の解釈、次の行動を別に設計します。討伐数を勇敢さや正義そのものへ変換しません。
累計、受注後、特定の同行や約束の期間を区別します。累計差分から復元できない同行中の討伐、連勝、行動順は、必要ならその文脈を含む出来事を追加記録します。記録されていない履歴を推測で補いません。
偽の報告や改竄台帳は世界内の文書・証言として持ち、客観的な戦績の正本を改変しません。
## 15.2 時間と画面外の行動
時計の単位、何によって進むか、評価地点、同時刻の完了と締切の優先順、中断中の扱いを宣言します。読む速さや現実の放置時間で、説明なく人物の死を決めません。
NPCは本人の取得情報と計画から判断し、実行は世界の実際の条件で検査します。通知を受けた、出発した、捜索した、対象を発見した、運搬した、という画面外の出来事も、通常の行動契約へ接続します。
競合する行為には順序または競合解決規則を置きます。NPC同士の反応が無限に呼び合わない停止条件も持たせます。汎用AIや全世界シミュレーターは必須ではなく、明示的な有限分岐でも実現できます。
## 15.3 保存・再開
保存には、必要な世界状態、進行ノードと待機位置、認識・提示履歴、時計、保留中の行為、処理済み出来事、予約行動、乱数状態を含めます。同じ保存状態と入力・判定結果から、同じ物語上の結果を再現できるようにします。
旧版から一意に復元できる値には根拠を付けて移行します。曖昧な値は旧経路の継続や明示した再開方針で扱い、新版の成功に便利な値を付与しません。報酬・物品・救助の二重取得と、保存された停止点の取り違えを防ぎます。
# 16. グラフ投影と変形操作
## 16.1 四つのグラフ
因果・動機グラフは、出来事、目的、作用機構、制度、根拠の関係を表します。必要条件、原因、許可、動機、証拠の支持をエッジの種類として分けます。
実行グラフは、場面・行動・判定・更新・合流・終端を表します。検査する実行状態は、ノードと、必要な世界状態・認識・提示履歴・時計・保留行為の組です。
情報・開示グラフは、観測、証言、仮説、推論、提示、Revealの依存関係を表します。証拠のAND・ORと、主人公の取得・読者への提示を区別します。
意味・回収グラフは、仕草、品物、台詞、約束、人物への評価がどこで読み直されるかを表します。感情的な応答を実行条件と混ぜません。
四つは共通IRから投影します。図を別の正本として手直しせず、参照IDから本文と条件へ戻れるようにします。根拠関係も因果・動機または情報グラフの型付き関係として扱い、独立した第五の真実を作りません。
## 16.2 Transformation / Operator
世界への操作は、過去の事件、資源、所有、法則、制度、外部への波及を変えます。人物への操作は、目的の優先順、信念、負い目、共有する価値、許せる手段を変えます。
提示への操作は、結果先行、視点交換、証言順、再訪、名称、台詞と動作の組合せを変えます。受け手・開示への操作は、犯行や保護の理解、成功や責任の読み方を変えます。介入への操作は、証拠を得る問題を、誰にいつ示すかという問題へ変えるなど、プレイヤーの行為の意味を変えます。
各操作に、入力条件、変更箇所、保持する事実、影響する行動・状態・開示・結末、狙う感情、再検査する契約を持たせます。目的の変更はGoal Transition、制度や機構の変更は該当契約へ反映します。作者の改稿とプレイ中の状態更新を区別します。
# 17. 結末と報酬
Ending Contractには、到達条件、終了時に必要な状態、成立した出来事、各人物の目的の帰結、関係と約束、負担を負った者、判明した範囲、残る問題、経路別本文、最後の具体的な像、報酬と一回性、終了後へ保存する差を記します。
契約達成、真相把握、救助、制度上の決着、信用、感情的な和解は別軸です。救助に成功しても原因調査が終わらない場合があり、真相を知っても被害を取り戻せない場合があります。
結末の各重要断定は、必要な状態と出来事に加え、作用機構・推論・制度・合意実行の根拠へ接続します。計画、約束、実施、確認、維持のどこまで成立したかを明記します。結末IDへ到達しただけで全達成を与えません。
報酬はゲーム上の報酬と、世界内で誰が何の条件で払う対価かを分けます。抽象的なゲーム報酬ならその扱いを宣言できます。不正を暴かれた依頼人が支払う設定なら、支払いの理由や保証も必要な範囲で定めます。報酬額を作者の道徳的な正解表示にはしません。
初回確定と再表示を区別し、報酬や制度変更を再発生させません。プレイヤーが経験していない会話や関係を結末の感動の前提にせず、必要なら同じ世界結末でも提示を変えます。
主題は、結末で説明するだけでなく、変わった振る舞いや残された物に表します。説教を除いても何を引き受けたかが伝わるかを読み直します。

# 19. 生成・改稿の手順
## 19.1 入力と通常状態
作品の長さ、ジャンル、既存の固定設定、プレイヤーの介入範囲、対象媒体、利用可能な機能と版を確認します。未指定の通常の補足は制作上の仮定として明示して進め、既存条件と矛盾する変更を無断で採用しません。
Dramatic Kernel、通常運用、今回崩れた理由、固定過去、開始状態、依頼成立を作ります。場面数や結末数から人物を逆算しません。指定された数がある場合も、意味のない場面や結末で水増しせず、その制約内で展開を再設計します。
## 19.2 人物と根拠
人物の知識・目的・価値・企み・代案を作り、主要行為の理由を結びます。目的が変わるなら、きっかけ、解釈、変更前後を定義します。
必要な作用機構、制度、証拠と推論、解決の同意・費用・人手・時間を定義します。結末から冒頭へ逆にたどり、成功や失敗に必要な根拠が途中に存在するか確認します。
## 19.3 代案と選択
非介入、通常の担当者への連絡、簡単な別解、早期開示を検査します。成立する代案を排除するために場当たり的な禁止を増やさず、必要なら筋書き自体を変えます。
各選択を、その時点の情報と負担から選びうる行為として設計します。選択前に必要な説明、推理の手掛かり、後で開示する情報を分けます。
## 19.4 状態・場面・演出
対象ID、場所、接続、身体、保持、数量、時計、状態台帳を整えます。行動の成功・失敗・中断、合流後の差、結末条件を定義します。
SceneとBeat、視点、提示順、伏線、再訪時の本文、最後の具体的な像を作ります。作者用の設定を台詞へ順番に貼り付けません。情報を隠す場所だけでなく、行為で伝える場所も設計します。
## 19.5 変換・検査・差戻し
共通IRから実行グラフ、本文、ゲーム出力またはゲームブックを生成します。実行に使う条件と本文の条件が一致するかを確認します。
第20章の検査を行い、違反ごとに原因の契約へ戻って改稿します。誤った本文だけを直す場合と、設定・機構・人物・分岐から直す場合を区別します。根拠側を変えたら影響する経路と結末を再検査します。
必要な原稿を未完成のまま提示して承認を求める手順にはしません。制作範囲内で修正できる不備は生成側で直します。固定されたユーザー条件同士の衝突など、作者が決められない事項だけを、完成した部分と具体的な選択点を示して確認対象にします。
# 20. 検査基準・差戻し・完了判定
## 20.1 検査の種類を分ける
構造検査は、型、参照、初期値、更新者、数量、所在、接触、能力、時計、再実行、保存、状態付き経路、本文条件、終了条件を対象にします。
意味の検査は、依頼成立、因果の機構、動機、制度、推論、交渉、代案、選択理由、設定の影響を対象にします。自然文の論理を完全に自動証明できるとは仮定せず、人またはAIによる本文と根拠の照合を含めます。
演出の検査は、人物の固有性、企みへの応答、情報の順序、選択の責任、伏線の読み直し、文章の間、感情的な帰結、作品群の多様性を対象にします。検査主体が同じAIでも、作者用設定を参照する点検と、提示された本文だけを読む点検を分けます。
## 20.2 九つの追加検査ID
V12-SITUATION：通常運用、今回の破綻、発見、依頼人の認識、外部へ依頼する理由がつながっていること。役職名を言い換えただけで業務が不明なら差戻します。
V12-MECHANISM：原因・介入・結果が、対象範囲、量、時間、適用条件を通してつながっていること。警報の停止を増水の解消と扱う、時間分散だけで使用総量が減ると扱う場合は差戻します。
V12-GOAL：目的の発生・変更に、その人物へ届いた出来事と判断根拠があること。後から生じる副目的を、受注時からの要求として描いた場合は差戻します。
V12-INSTITUTION：権利・義務・資格の効力、判断権限、証明、執行、当該経路で問題になる例外が整合すること。原本の保持だけで、未定義の失効や処罰を発生させた場合は差戻します。
V12-INFERENCE：取得した証拠が、実際の断定の範囲を支えること。記録欠落や物性の観測から、必要な補助前提なしに犯人・安全・給金不足まで確定した場合は差戻します。
V12-RESOLUTION：解決の同意または強行の条件、資源、実行者、時間、確認、維持が対応すること。提案や試験だけで合意・工事・長期運用を完了させた場合は差戻します。
V12-ALTERNATIVE：非介入と目につく代案を検討し、選べない理由を人物・世界・介入範囲のいずれかで説明できること。有効な別出口を無視して全救助不能と断定する場合は差戻します。
V12-CHOICE：選択時点の情報、見通し、負担、意図と実際の作用が対応すること。知っていることを経路間で混ぜる、選択に含まれない重大行為を追加する、選ぶ理由のない愚策だけを比較対象にする場合は差戻します。
V12-ASSUMPTION：追加設定の出典・採用・範囲・依存先を明示し、影響先と提示の必要度を検査すること。注釈に書いたことだけで整合確認済みとする、結末後の規則を過去へ流用する場合は差戻します。
## 20.3 構造・経路の継承検査
参照される全実体が存在し、初期状態が固定過去と一致することを確認します。所在の一意性と包含の非循環、接続、能力、保持者、数量の非負、容量、収支を検査します。
表示・実行・成功提示の条件、戦闘勝利前後、敗北・逃走・拒否・資源不足、合流・再訪、報酬の一回性、通知前後、情報の取得時点、期限の境界、保存・再開・移行を確認します。
有限状態の全探索、深さを限った探索、代表経路の実行、静的検査、本文レビューを区別します。抽象化した反例は必要に応じて具体的な状態へ戻して確認します。上限付き探索を全経路の証明とは呼びません。
## 20.4 網羅性と検査結果の状態
coverageには、重要な依頼・行為・目的変更・推論・合意・結果・本文断定を列挙し、対応する契約、検査方法、対象経路、結果を結びます。契約から本文だけでなく、本文から契約への対応も点検します。
検査状態はpass、fail、needs_review、not_run、not_applicableを区別します。not_applicableには理由、passには実施方法・根拠・対象版、failには再現内容を必要とします。単に検査名が存在することはpassの根拠ではありません。
重大な行為や結末の根拠が未定義、対応する意味検査が未実施、構造違反が未修正の場合は、当該範囲をv1.2準拠の完成品としません。部分対応なら、対応範囲と未解決事項を明示します。無関係な検査の点数で相殺しません。
## 20.5 差戻し報告
各問題は、シナリオIDと版、対象経路または本文位置、問題の断定・行為、対応検査ID、利用可能な根拠、欠けた条件または反例、期待と実際、修正方針、影響先、再検査の結果を持ちます。
状態矛盾には最後の更新イベントを、意味の飛躍には結論を覆す具体的な別解や不足条件を示します。「説得力がない」だけで止めません。初期設定の問題なら、その初期条件自体を再現単位とします。
差戻し先は、Situation、Mechanism、Goal Transition、Institution、Inference、Resolution、Choice、Presentationなど原因の定義へ向けます。設定を変えたのに本文だけ再読して終えず、依存先の検査結果を古い版として無効化し、必要な範囲を再確認します。
## 20.6 物語としての完成
Coherence、Causal Necessity、Character Necessity、Economy、Surprise、Fairness、Retrospective Gain、Emotional Payoffを別々に見ます。加えて、介入の意味、経路ごとの成立、情報境界、媒体変換、作品群の構造差を確認します。
人物名を替えても同じか、情報を早く渡しても人物が行動できるか、分岐を削ると何が失われるか、説教を削っても主題が残るかを点検します。これらは一律の失格式ではなく、生活感・緩急・小さな態度表現を残すための判断を伴います。
モデルが保証できるのは、定義した条件と実施した検査の範囲です。人物の深さや面白さを機械的に保証しません。その限界を理由に、具体的な矛盾や飛躍の検査を省略することも認めません。
# 21. q005による設計例と検査例
## 21.1 例の範囲
以下は、カタログの「主目的は排水の回復」「試験後に保存の副目的が生じる」「食用確認は別に行う」を、v1.2の契約へ接続する部分設計例です。資源の確保や記録項目の詳述はこの例で補います。現行JSONを変更・実行した結果ではありません。
既存の素材を保ちながら、何を追加で決めなければならないかを明示します。この例の資源や手続を、他の作品の必須設定にはしません。
## 21.2 状況と初期状態
依頼の主目的G_restartは、本管の詰まりを除き、排水できる状態にして工房を再開することです。菌床は旧排水溜めにあり、本管には詰まりが残っています。トトは保存の可能性や食用の可否をまだ確認していません。
この例ではトトが工房設備の変更を判断する権限を持つと補足します。ただし、その権限だけで資金、工事の技能、空き槽、冷水供給まで保有すると推論しません。分離案を実行する経路で個別に確認します。

## 21.4 分離案と完了条件
分離案のResolutionでは、トトの承諾、使える空き槽、管理に足りる冷水、工事に必要な人手と技能、費用と維持の引受けを確認してから作業へ進みます。不足した条件があれば、その場で調達・再交渉するか、別案へ進みます。
菌床の移動だけでは本管に残った泥は消えません。菌床と濾材の移設、残存する詰まりの除去、配管、実際の排水試験をそれぞれ出来事として持ちます。短い一場面へまとめても、結果を区別して記録します。
食用については、採取した試料・採取経路・試験条件・対象範囲・判断根拠を別のInferenceへ接続します。「甘い」「排水に直接触れていない」という性質だけを、安全性の証明にしません。試験を通した分についてのみ利用する、という範囲を結末へ引き継ぎます。試験法の実在的な妥当性を本例が保証するものではなく、作品で採用する判断基準を定義する必要があります。
この例の保存成功の結末には、主目的としての排水回復、菌床の保存、当該範囲の利用確認、維持の引受けを個別に要求します。保存には成功しても食用確認ができない場合、食用糖液を得たとは書きません。
## 21.5 選択と演出
焼却は、保存の可能性を失う代わりに、菌床の継続管理を引き受けず詰まりの原因を除く行為として比較できます。網による維持は、初期の工事を抑えられる条件がある場合に、その利点と清掃負担を示します。条件がなければ、安上がりだと自動的に描写しません。
保存案も、何も失わない最上位の選択とは決めません。設備変更の費用や維持、確認できる範囲を、実際の設定に応じて扱います。焼却を選んだ人物を、それだけで浅慮や悪人とは評価しません。
演出では、当初は泥を嫌がっていたトトが、試験後には試料を丁寧に扱い始める、といった行為で目的の変化を伝えられます。本文にGTの説明欄を読み上げさせず、変化のきっかけが読者へ伝わるようにします。
