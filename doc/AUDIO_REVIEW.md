# BGMの試聴と記録

リポジトリをフォルダごと展開し、[audio-review.html](audio-review.html) を直接開きます。サーバーや開発コマンドの実行は不要です。40曲の配布用Oggを使い、音量の初期値もゲームと同じ35%です。試聴中の変更はゲームの設定には反映しません。

## 聴き方

曲を選び「再生」で音色と作品の雰囲気を確かめます。「3周再生」は冒頭から始め、3回目の終わりで停止します。途中の一時停止は同じ周から再開できます。「末尾5秒から聴く」は末尾へ移動し、そのまま冒頭へつないで繰り返します。曲を変更すると再生は止まり、その曲の記録に切り替わります。

曲ごとに音色、音量・圧縮による音の変化、継ぎ目のクリック音・無音、3周通した聴こえ方を確認します。気になるところでは「再生位置を記入」で時刻をメモへ入れられます。曲を変えて音量を比較する際は、各曲の初期音量で聴いてください。

確認欄と判定は試聴者が付けます。再生が3周しただけではチェックされません。「問題なし」は4項目を確認した場合だけ選べます。「要修正」は途中でも記録できます。OS、ブラウザ、スピーカーやヘッドホンを試聴環境へ書いてください。40曲は合計約60分44秒、全曲を3周ずつ聴くと約182分11秒です。

## 記録を続ける

メモ・確認欄・判定・試聴環境は、ゲームの栞とは別のキー `gamebook.audio-review.v1` へ自動保存します。ブラウザの保存が使えない場合は画面に表示するので、「記録をJSONで保存」で持ち出します。別の環境へ移る場合も、JSONを保存して「記録を読み込む」で続きを行えます。

読込は同じ音源の曲別記録を反映し、ファイルに含まれない曲の記録は保持します。音源のSHA-256が異なる記録は現在の確認済み扱いにせず、JSONの `archive` 欄へ残します。素材更新後に以前の自動保存を開く場合も、該当曲を未確認へ戻し、以前のメモは同じ欄へ保持します。形式が不正な記録は、現在のメモを変更せず拒否します。

## 確認済みの範囲と残っていること

**全40曲の数値測定は済んでいます。耳による音色評価と全曲3周の連続試聴は未実施です。今回の操作確認は[検証記録](VALIDATION.md)を参照してください。**

測定値と音源のSHA-256は[sources/audio/render-report.json](../sources/audio/render-report.json)にあります。共通本棚・短編の21曲は統合音量−17.98〜−17.96 LUFS、最大true peak−3.38 dBTP。中編3曲は93.33〜105秒、−17.95〜−17.94 LUFS-I、最大true peak−7.26 dBTPです。追加したGB21〜GB24の4曲は87.27〜96秒、−17.96〜−17.95 LUFS-I、最大true peak−7.76 dBTPです。GB25〜GB28の4曲は90〜96秒、−17.96〜−17.93 LUFS-I、最大true peak−6.67 dBTPです。GB29〜GB32の4曲は90〜96秒、−17.95〜−17.94 LUFS-I、最大true peak−7.93 dBTPです。GB33〜GB36の4曲は90〜96秒、−17.95 LUFS-I、最大true peak−7.84 dBTPです。これらは信号の測定値で、音色や圧縮品質を耳で評価した結果ではありません。

2026年10月23日の[PR #14のCI](https://github.com/TomTomYoung/GAMEBOOK/actions/runs/39961640683)で、24曲を対象にLinuxのChromium・Firefox・WebKitで試聴ページの操作試験が成功しました。再生・停止、継ぎ目の通過、3周後の停止、曲別記録の保存・復元・出入、不正形式と旧音源の扱い、PCとスマホ幅の表示を確認しています。各成果物の `audio-review/` に結果があります。

3周停止の操作試験では時間を短縮するため各周の末尾へ移動しています。全曲を3周聴いたという意味ではありません。試聴者が実際に聴き、確認欄・判定・環境を記録してください。報告された曲と位置をもとに修正し、音源を更新した場合はその曲を再確認します。Safari実機・実機OS別の確認も残っています。

[2026年10月20日の21曲時点の試験結果](validation/audio-review-browser.json)は履歴として保持しています。24曲時点の操作確認は上記CI、現在の40曲に対する結果は[検証記録](VALIDATION.md)を参照してください。

## 開発時の確認

`npm run build`で試聴データも生成します。`npm run check`は、音源の変更に対してそのデータが古くなっていないか検査します。画面の操作試験は `node tests/audio-review.browser.cjs` です。`BROWSER`・`CHROMIUM_PATH`・`QA_OUTPUT_DIR`環境変数に対応し、CIでは3ブラウザで実行します。

試聴ページは制作資料のため、通常のゲーム公開用ファイルには含めません。ゲームを遊ぶ人や試聴する人は、生成コマンドを実行する必要はありません。
